本页指 [BigPizzaV3/CodexPlusPlus](https://github.com/BigPizzaV3/CodexPlusPlus) 的**桌面管理工具**，不是另一个同名命令行项目，也不是官方 Codex 自带的设置页。下文按 **v1.2.56** 核对；版本不同，按钮位置可能变化。

还没安装？先看 [安装与打开工具](/start/install-tools)。安装后会有 **Codex++** 和 **Codex++ 管理工具** 两个入口：前者启动你实际用的桌面应用，后者负责配置。

<Warning>先保存正在运行的任务、备份原配置。不要同时让 CC Switch 和 Codex++ 管理同一套 Codex 配置。这一页不要求删除官方账号，也不需要修改会话记录。</Warning>

## 1. 打开管理工具，添加供应商

先打开 **Codex++ 管理工具**，在 **概览** 确认它能找到官方应用。然后进入 **供应商配置**，点击 **添加供应商**。

若页面显示供应商配置切换的总开关，需要开启这一功能；它与“保存一张供应商卡片”不是一回事。

## 2. 选择纯 API，填写 Faro

第一次先使用 Faro 支持 **Responses** 的模型，不要同时设置多家聚合和协议转换。

下图按 **v1.2.56** 的字段重建，省略非必要选项，是填写示例，不是实际运行截图。占位 Key、模型名要换成自己的值；点击图片可放大。

<Frame><img src="/images/codex-plus-pure-api.png" alt="Codex++ v1.2.56 纯 API 填写示例：无需认证关闭，Base URL 为 https://faroapi.com/v1，Responses API，默认模型" /></Frame>

| 界面字段 | 填什么 |
| --- | --- |
| 名称 | `Faro API` |
| 接入模式 | **纯 API** |
| Base URL | `https://faroapi.com/v1` |
| Key | 你在 Faro 令牌管理里创建的密钥 |
| 无需认证 | **关闭**，Faro 调用需要密钥 |
| 上游协议 | **Responses API** |
| 默认模型 | 从 Faro 复制的完整模型 ID |

<Note>不要省掉地址末尾的 `/v1`。这个版本获取模型列表时可能自动补路径，所以“获取成功”并不能证明你填写的地址适用于后续对话。</Note>

点击 **从上游获取** 可尝试读取这枚令牌能看到的模型，再选中要用的模型。获取失败时先核对地址、密钥和令牌权限；也可以从 [Faro 模型广场](https://faroapi.com/pricing) 复制完整名称到默认模型，不能随便猜一个名字。

模型 ID 的真实线路、规格后缀要保留。软件中“不要带后缀”一类提示可能针对它自己的窗口扩展写法，**不代表可以删掉 Faro 模型名里的后缀**。拿不准就把不含密钥的截图和完整模型名交给支持确认。

上下文长度、推理强度等先按模型支持范围或默认设置使用，不要照着视频统一拉到最大。会话身份保持默认；混入官方、Sub2API 专用倍率、自定义 User-Agent 等不属于本教程的必要设置，不用开启。

## 3. 保存，并设为当前

点 **保存** 回到列表，再点 Faro 卡片的 **使用**；也可以进入供应商详情，点底部 **设为当前**。卡片出现 **使用中**，才表示选中了这份供应商配置。

如果你只是点了保存就关闭窗口，下一次可能仍使用原来的供应商。

## 4. 从 Codex++ 启动

先正常结束任务并退出原来的桌面应用，不要强制结束正在工作的进程。回到管理工具的 **概览**，点 **启动 Codex++**，或使用安装时创建的 **Codex++** 入口。

不要再点击原版应用的快捷方式来验证这次配置，否则可能没有加载管理工具的配置。若提示找不到应用，回到概览检查应用路径，而不是重新充值或换密钥。

## 5. 发一句短话，到 Faro 确认

在打开的桌面应用中**新建一个对话**，选择刚才的模型。先发送：

```text
只回复“连接成功”，不要读取文件或调用工具。
```

这次请求可能计费。收到回复后打开 [Faro 使用日志](https://faroapi.com/console/log)，按时间、令牌和完整模型名核对。模型自己说“我是某某”不能作为线路证明，管理器里的测速也不能代替这一步。

以后使用 Faro，保留 **使用中** 状态并从 **Codex++** 入口启动。要换回原方式，在管理工具中切回原有供应商/模式后，正常退出并重新启动应用；不要删除旧登录文件。

## 常见卡点

- **管理器里能获取模型，聊天却 404**：检查 Base URL 是否完整为 `https://faroapi.com/v1`，并确认该模型支持 Responses。
- **保存了但没生效**：检查是否 **设为当前**、是否从 Codex++ 入口启动、是否新建了对话。
- **文本正常，图片或工具调用失败**：这些是额外能力，需要模型和线路同时支持，不能只凭文本成功就认定全部可用。
- **Claude 线路限制 Claude Code**：改协议或伪装客户端不能解决；请改用该线路允许的客户端。

其他错误看 [常见报错](/help/errors)。仍不确定时，用 [反馈模板](/help/contact) 提供软件版本和卡住的步骤，不要发送 Key。
