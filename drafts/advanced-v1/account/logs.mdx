---
title: "用日志确认请求和用量"
sidebarTitle: "查看使用日志"
description: "配置好后，先在日志里找一条刚刚发出的请求。"
---

打开 [使用日志](https://faroapi.com/console/log)，把时间范围设到刚才测试的时间，再按令牌名称或模型筛选。找不到时先清除筛选条件，确认登录的是创建密钥的那个账号。

| 字段 | 看什么 |
| --- | --- |
| 时间、令牌、模型 | 是否和刚才的请求对应 |
| 类型与详情 | 是正常消费，还是返回错误；展开看完整说明 |
| 输入 / 输出 | 发给模型和模型生成的内容量 |
| 缓存读取 / 缓存写入 | 两种费用不同，不能混为缓存命中 |
| 首字 / 耗时 | 开始输出前等多久，以及整次请求持续多久 |
| 花费 | 这条日志记录的扣费 |

## 收到了回答，却找不到 Faro 日志

先确认客户端启用的是 Faro 供应商。切换配置后，旧会话或没有重启的客户端可能仍在使用原配置。新建对话后再发一次短请求，并刷新日志。

## 看到错误记录

记下时间、模型和完整错误文字。不要只截最后一行，也不要为了截图露出 API Key。查看 [报错排查](/help/errors)。

<Note>客户端的一次任务可能包含多次模型调用、工具循环或重试。不能用「我只发了一句话」推断只产生一条请求。</Note>
