| 报错 | 先检查什么 | 下一步 |
| --- | --- | --- |
| 401 / 密钥无效 | 是否粘贴完整、是否误填网站密码 | 检查令牌状态，必要时重新创建 |
| 403 / 被策略屏蔽 | 完整错误是否提到客户端、会话或内容限制 | 停止反复重试，核对允许的客户端并联系支持 |
| 404 / model not found | 地址路径、模型名、分组和权限 | 去模型广场复制完整 ID，检查是否重复 `/v1` |
| 400 / invalid parameter | 错误指出哪个参数不支持 | 删除或改正该参数；原样重试通常没用 |
| 额度不足 | 账号余额与当前令牌额度 | 在钱包和令牌管理分别确认 |
| 429 / 请求过多 | 请求频率、并发量、上游限额或额度说明 | 暂停并行任务，按提示等待，避免密集重试 |
| 500 / 502 / 503 / 504 | 完整错误、监控状态、是否仅一个模型失败 | 保存时间和错误，稍后单次重试或联系支持 |
| HTML 页面 / 页面不存在 | 是否把网页地址填成了 API 地址 | 按地址对照表检查完整请求路径 |

## 两种容易误判的情况

**“No available channel”**：当前模型在该分组没有可用路由，不等于整个网站都坏了。检查准确的模型名和分组，再看监控。

**“Only … models are supported” / “convert_request_failed”**：可能选错接口或协议。比如某个图片模型不支持 `/v1/images/generations`，需要另一种调用方式。换密钥通常解决不了协议不匹配。

## 关于客户端限制

部分模型线路限定了可使用的客户端。通用 HTTP 请求或监控探测失败，不足以证明指定客户端也不能使用；反过来，监控显示正常，也不能保证所有工具配置都正确。

请使用线路明确支持的客户端。不要通过伪造请求头或反复尝试绕过限制。若你已经在支持的客户端中使用，提供错误正文和时间给支持人员核对。

## 仍然解决不了

按 [反馈模板](/help/contact) 提供必要信息。API Key、密码、Cookie 一律不要发送。
